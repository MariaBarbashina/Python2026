## Формат входного файла

- Кодировка UTF-8.
- Первая строка: два положительных целых числа через пробел — количество строк и столбцов.
- Далее ровно указанное количество строк, в каждой ровно указанное количество целых чисел через пробелы.
- Пустые и лишние строки считаются ошибкой. Допустим один обычный перевод строки после последней строки данных.
- При ошибке формата `read_matrix` выбрасывает `ValueError` с пояснением и номером строки (нумерация с 1, заголовок — строка 1). Отсутствующий файл — `FileNotFoundError`, неверная кодировка — `UnicodeDecodeError`.

```text

```

## Ответы на вопросы защиты

- **Ошибки формата и ошибки доступа.** Ошибка формата (`ValueError`) означает, что файл прочитан, но его содержимое не соответствует правилам: нет заголовка, не число, не та длина строки. Исправлять нужно данные. Ошибка доступа (`FileNotFoundError`, `PermissionError` и другие `OSError`) означает, что файл вообще не удалось открыть или прочитать. Исправлять нужно путь, права или окружение. Неверная кодировка (`UnicodeDecodeError`) обрабатывается отдельно и раньше `ValueError`, потому что является его подклассом.
- **Почему отчёт открывается для записи после проверки входа.** Режим `"w"` стирает содержимое файла сразу при открытии. Если открыть `report.txt` до проверки, то при ошибке во входных данных старый отчёт пропадёт, а новый не будет записан. Поэтому сначала полностью читается и проверяется `matrix.txt` и формируется текст отчёта, и только потом открывается `report.txt`. Входной файл открывается только в режиме `"r"`.
- **Почему CSV пишется через модуль `csv`.** Значения могут содержать запятые, кавычки и переводы строк. Модуль `csv` экранирует их по правилам формата, а ручной `split(",")` такие значения сломал бы.
