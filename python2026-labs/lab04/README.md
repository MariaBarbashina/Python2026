## Трассировка цикла суммирования чисел 1–4

```python
total = 0
for number in range(1, 5):
    total += number
```

| Итерация | `number` | `total` до | `total` после |
|---|---|---|---|
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |

После четвёртой итерации `range(1, 5)` заканчивается: значение `5` в последовательность не входит. Итог `total = 10`.

## Ответы на вопросы защиты

- **Почему циклы завершаются.** Цикл `for` перебирает конечную последовательность `range` и останавливается, когда значения заканчиваются. В `positive_input.py` цикл `while number <= 0` в каждой итерации получает новое значение `number`; как только пользователь вводит положительное число, условие становится ложным. В `prime.py` `divisor` растёт на 1 в каждой итерации, поэтому `divisor * divisor` рано или поздно превысит `n`; при найденном делителе цикл завершается раньше через `break`.
- **Почему `range(a, b)` не подходит для задания 1.** `stop` не входит в диапазон, поэтому `range(2, 4)` даст только `2, 3`, без `4`. Кроме того, при `a > b` и шаге по умолчанию `+1` диапазон пустой. Нужны `range(a, b + 1)` по возрастанию и `range(a, b - 1, -1)` по убыванию.
- **Почему максимум инициализируется первым значением.** Если начать с `maximum = 0`, то для набора `-5, -2, -8` ответ ошибочно будет `0`. Поэтому на первой итерации (`index == 0`) максимумом становится первое введённое число.
- **Почему в `prime.py` достаточно проверять делители до `sqrt(n)`.** Если `n = a * b` и `a <= b`, то `a * a <= n`. Значит, у составного числа обязательно есть делитель не больше `sqrt(n)`.
