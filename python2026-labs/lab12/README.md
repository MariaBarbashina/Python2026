# Итоговый проект. Учёт печатных заказов

**Выполнила студентка группы УМ-262 Барбашина Мария Назаровна**

| | |
|---|---|
| **Автор** | Барбашина Мария Назаровна, группа УМ-262 |
| **Вариант** | 10 — учёт печатных заказов |
| **`amount`** | количество страниц |
| **`completed`** | заказ напечатан |
| **Версия Python** | 3.12 (проверено), подходит 3.12 и новее; внешние библиотеки не нужны |

## Назначение

Консольная программа для учёта печатных заказов. Она хранит список заказов в `data.json` и позволяет:

- просматривать, добавлять, искать и удалять заказы;
- отмечать заказы как напечатанные или не напечатанные;
- смотреть статистику: сколько заказов, сколько напечатано и не напечатано, сколько всего страниц и сколько страниц в каждой категории.

Программа работает локально, интернет не нужен.

## Как запустить

Из папки проекта (`lab12`):

```text
python main.py
```

Автоматические проверки:

```text
python test_logic.py
python test_storage.py
```

Дополнительное задание — окно поиска (tkinter):

```text
python gui.py
```

Пути строятся от папки скрипта (`Path(__file__).resolve().parent`), поэтому проект запускается после копирования в любую другую папку без изменения путей.

## Структура

| Файл | Ответственность |
|---|---|
| `main.py` | Консольное меню, ввод с повторением, сообщения, вызовы функций |
| `logic.py` | Проверка записей, добавление, поиск, изменение статуса, удаление, статистика. Без ввода-вывода и файлов |
| `storage.py` | Чтение и запись JSON. Без консольных диалогов |
| `test_logic.py` | Автоматические проверки логики |
| `test_storage.py` | Автоматические проверки хранения (во временной папке) |
| `data.json` | Вымышленный набор из 5 заказов |
| `gui.py` | Дополнительное задание: окно поиска и просмотра на tkinter |

Состояние программы — список `records` внутри `main()`. Он передаётся в функции параметром, глобальные изменяемые переменные не используются.

### Контракты функций logic.py

| Функция | Изменяет список? | Результат |
|---|---|---|
| `validate_records(records)` | нет | ничего; при нарушении — `ValueError` с номером записи |
| `add_record(records, title, category, amount)` | **да**, добавляет в конец | новая запись; при некорректных данных — `ValueError`, список не меняется |
| `find_records(records, query)` | нет | список найденных записей по возрастанию ID; пустой запрос — `ValueError` |
| `set_completed(records, record_id, completed)` | **да**, меняет одну запись | `True` при успехе, `False` при неизвестном ID (данные не меняются) |
| `delete_record(records, record_id)` | **да**, удаляет запись | `True` при успехе, `False` при неизвестном ID (список не меняется) |
| `statistics(records)` | нет | словарь `total`, `completed`, `not_completed`, `amount_total`, `by_category` |
| `next_id(records)` | нет | максимальный ID плюс 1, для пустого списка — `1` |
| `sorted_records(records)` | нет | новый список по возрастанию ID |

| Функция storage.py | Поведение |
|---|---|
| `load_records(path)` | Читает JSON в UTF-8 и проверяет весь набор. Файл никогда не перезаписывает. Ошибки: `FileNotFoundError`, `UnicodeDecodeError`, `json.JSONDecodeError`, `ValueError`, `OSError` |
| `save_records(path, records)` | Пишет во временный `data.json.tmp`, затем заменяет им `data.json`. При ошибке — `OSError`, прежний файл не меняется |

## Формат данных

`data.json` — список записей в UTF-8:

```json
[
  {"id": 1, "title": "Курсовая работа по истории", "category": "переплёт", "amount": 45, "completed": true},
  {"id": 2, "title": "Рекламные буклеты для кафе", "category": "цветная печать", "amount": 120, "completed": false}
]
```

Правила:

- Корень — список, каждая запись — объект. Все пять полей обязательны, дополнительные ключи сохраняются без обработки.
- `id` — положительное целое, уникальное. Новый ID равен максимальному ID плюс 1, для пустого списка — `1`. После удаления ID не перенумеровываются.
- `title` (название заказа) и `category` (вид печати) — непустые строки. При добавлении пробелы по краям удаляются.
- `amount` — количество страниц, целое не меньше 0. `true` / `false` вместо числа не принимаются.
- `completed` — строго `true` или `false`.

### Вымышленный набор и ожидаемая статистика

| ID | Название | Категория | Страниц | Напечатан |
|---|---|---|---|---|
| 1 | Курсовая работа по истории | переплёт | 45 | да |
| 2 | Рекламные буклеты для кафе | цветная печать | 120 | нет |
| 3 | Методичка по Python | чёрно-белая печать | 80 | да |
| 4 | Афиши для концерта | цветная печать | 30 | нет |
| 5 | Дипломная работа | переплёт | 90 | нет |

Статистика, рассчитанная вручную:
- всего 5 заказов, напечатано 2, не напечатано 3;
- страниц 45 + 120 + 80 + 30 + 90 = **365**;
- по категориям: переплёт 45 + 90 = **135**, цветная печать 120 + 30 = **150**, чёрно-белая печать **80**.

Совпадает с выводом программы и с проверкой в `test_logic.py`.

Что проверено:
- **Пустой список:** статистика из нулей, поиск, статус и удаление при неизвестном ID.
- **Повторяющиеся названия** допустимы и получают разные ID.
- **Строгие типы:** `id=true`, `amount=true`, `amount="10"`, `amount=1.5`, `amount=-1`, `completed="false"`, `completed=0`, пустые `title` и `category`, отсутствие каждого из пяти полей, повторный `id`, корень-объект.
- **Неизвестный ID:** функции возвращают `False`, данные не меняются.
- **Поиск без учёта регистра:** `PY` находит `Python`; результат по возрастанию ID; пустой запрос отклоняется.
- **Статистика по двум категориям,** включая категорию с пробелами по краям.
- **Удаление ID 1 из [1, 2]:** остаётся ID 2, новая запись получает ID 3.
- **Хранение (во временной папке через `TemporaryDirectory()`):**
  - сохранение и повторная загрузка восстанавливают все поля, статусы и кириллицу;
  - повреждённый и пустой файл, неверная кодировка, повторный ID обнаруживаются, повреждённый файл при чтении не меняется;
  - при ошибке записи прежний файл остаётся без изменений.

## Путь одной записи: от ввода до JSON и обратно

1. **Пункт 2 меню** (`main.add_command`). `read_text` и `read_amount` повторяют ввод, пока не получат непустые строки и целое число не меньше 0.
2. **`logic.add_record`.** Убирает пробелы по краям, ещё раз проверяет типы, назначает `id = next_id(records)` и `completed = False`, затем добавляет словарь в список `records`.
3. **Пункт 7 или выход с ответом `да`** (`main.save_command` → `storage.save_records`). Список записывается через `json.dump(..., ensure_ascii=False, indent=2)` во временный файл, а затем атомарно заменяет `data.json`.
4. **Следующий запуск** (`main.load_data` → `storage.load_records`). `json.load` читает файл, `validate_records` проверяет весь набор, и запись снова появляется в списке `records` с теми же полями и статусом.

## Ответы на вопросы защиты

- **Почему логика, хранение и интерфейс разделены.** `logic.py` можно проверить тестами без меню и без файлов. `storage.py` — без консоли. `main.py` и `gui.py` используют одни и те же функции, поэтому окно поиска не дублирует логику.
- **Почему файл проверяется целиком до начала работы.** Если загрузить часть данных и потом сохранить, повреждённый файл перезапишется неполной копией. Поэтому при любой ошибке загрузки программа сообщает причину и завершается, не открывая `data.json` для записи.
- **Почему сохранение через временный файл.** Режим `"w"` стирает файл сразу при открытии. Если запись прервётся, данные будут потеряны. Запись во временный файл и `os.replace` гарантируют, что `data.json` либо полностью новый, либо прежний.
- **Где добавлять доработку на защите.** Новый фильтр (например, только ненапечатанные заказы) — новая функция в `logic.py`, проверка в `test_logic.py` и новый пункт в словаре `commands` в `main.py`. Изменение вывода статистики — функция `statistics_command` в `main.py`.
