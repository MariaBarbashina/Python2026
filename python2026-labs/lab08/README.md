## Ответы на вопросы защиты

- **Выбор структуры.**
  - Частоты слов — `dict`: каждому слову (ключу) нужно сопоставить число, а поиск по ключу быстрый.
  - Учебные интересы — `set`: нужны уникальные темы и операции пересечения `&` и объединения `|`.
  - Пара «название, часы» — `tuple`: это неизменяемая пара фиксированной длины, удобная для распаковки `title, hours = pair`.
  - Записи заказов — список словарей: заказов много, порядок важен, а у каждого заказа есть именованные поля.
- **Почему запись удобно представить словарём.** Поля доступны по понятным именам (`record["hours"]`), а не по номерам позиций. Поле можно изменить (`record["hours"] = 6`) или добавить новое (`record["completed"] = False`), не перестраивая остальные данные. Код получается самодокументируемым.
- **Поведение `.get()`.** `counts.get(word, 0)` возвращает значение, если ключ есть, и `0`, если его нет, без `KeyError`. Поэтому `counts[word] = counts.get(word, 0) + 1` работает и для первого появления слова. Обращение `record["missing"]` к несуществующему ключу вызывает `KeyError`.
- **Почему множество сортируют перед выводом.** У множества нет индексов и гарантированного порядка, и при разных запусках порядок может отличаться. `sorted()` даёт список в предсказуемом порядке, поэтому результат можно сравнивать в тестах.
- **Аргумент `key` в `sorted()`.** `sorted(totals.items(), key=total_sort_key)` сортирует пары по значению, которое возвращает `total_sort_key`, — кортежу `(-total, category)`. Минус даёт убывание суммы, а при равных суммах кортежи сравниваются по второму элементу, то есть по названию по алфавиту.
