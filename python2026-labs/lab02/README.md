## Задание 3. Прогноз и результат Python

Прогноз сделан вручную до запуска `predict.py`.

| Выражение | Прогноз | Результат Python | Пояснение |
|---|---|---|---|
| `2 + 3 * 4` | `14` | `14` | Умножение выполняется раньше сложения: `2 + 12` |
| `(2 + 3) * 4` | `20` | `20` | Скобки выполняются первыми: `5 * 4` |
| `17 // 5` | `3` | `3` | Целая часть от деления `3.4` |
| `17 % 5` | `2` | `2` | `17 = 5 * 3 + 2` |
| `-7 // 2` | `-4` | `-4` | `//` округляет вниз, к минус бесконечности: `-3.5` → `-4`, а не `-3` |

Прогноз совпал с результатом. Ошибка была бы легко возможна в `-7 // 2`: деление округляет не «к нулю», а вниз. Проверка равенства: `-7 == (-4) * 2 + 1`, то есть `-7 % 2 == 1`.

## Ответы на вопросы защиты

- **`/` и `//`.** `/` — обычное деление, результат всегда `float`: `7 / 2 == 3.5`. `//` — деление с округлением вниз: `7 // 2 == 3`, `-7 // 2 == -4`.
- **Смысл остатка.** `a % b` — то, что остаётся после того, как из `a` выделили максимальное число целых `b`. Выполняется равенство `a == (a // b) * b + a % b`. В варианте это бутылки, которые не заполнили ящик целиком.
- **Почему форматирование не устраняет неточность `float`.** `:.2f` влияет только на вывод. Например, `0.1 + 0.2` хранится как `0.30000000000000004`, и при выводе через `:.2f` это число просто округляется до `0.30`, а хранимое значение остаётся неточным. Поэтому в денежных задачах используют целые рубли или копейки.
