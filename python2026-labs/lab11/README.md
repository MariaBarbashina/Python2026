## HTTP-упражнение

Интернет был доступен, поэтому выполнен один запрос для `octocat`:

```text
> python fetch_profile.py
Логин GitHub: octocat
Профиль сохранён: octocat
```

Ответ сохранён в `profile.json` без изменений. Поля с `null` не заменялись выдуманными данными. Изменяемые поля профиля (число подписчиков, дата обновления) на точное совпадение не проверяются. При пустом логине программа выводит `Ошибка данных: Логин не должен быть пустым`, и запрос не выполняется.

Файл `profile_sample.json` (`{"login": "demo", "id": 1, "name": null}`) — учебные локальные данные для режима без сети. Он читается через `json.load` в `profile_menu.py`.

### Пояснения к fetch_profile.py

- **Адрес** `https://api.github.com/users/<логин>` — ресурс GitHub REST API «пользователь по логину». Это профиль, а не репозиторий: для репозитория нужны владелец и имя (`/repos/<owner>/<repo>`). `quote(..., safe="")` экранирует логин, чтобы символы вроде `/` или пробела не изменили путь запроса.
- **GET** — метод чтения ресурса: запрос только получает данные и ничего не меняет на сервере. `urlopen` с объектом `Request` без тела выполняет GET. Заголовок `Accept` просит формат JSON GitHub API, `User-Agent` обязателен для API GitHub.
- **Таймаут** `timeout=10` ограничивает ожидание ответа 10 секундами. Без него программа могла бы зависнуть при медленной или недоступной сети.
- **Обработчики ошибок:**
  - `HTTPError` — сервер ответил кодом ошибки: `404` — нет такого пользователя, `403`/`429` — ограничение доступа или частоты запросов.
  - `URLError`, `TimeoutError`, `socket.timeout` — сеть недоступна, адрес не найден или истёк таймаут.
  - `ValueError`, `UnicodeError` — пустой логин, некорректный JSON или ответ, не похожий на профиль.
  - `OSError` — ошибки записи `profile.json`.

  `HTTPError` — подкласс `URLError`, а тот — подкласс `OSError`, поэтому обработчики стоят от частного к общему.

## Ответы на вопросы защиты

- **Почему отдельная проверка структуры.** Синтаксически правильный JSON может иметь неподходящую структуру: объект вместо списка, `"completed": "false"` строкой, повторный `id`. `json.load` такие данные примет, поэтому `validate_todos` проверяет каждое поле.
- **`type(value) is int`, а не `isinstance`.** `bool` — подкласс `int`, поэтому `isinstance(True, int)` истинно, и `id=true` прошёл бы проверку. Строгая проверка типа отсекает логические значения.
- **Порядок обработчиков.** `json.JSONDecodeError` — подкласс `ValueError`, поэтому его обработчик стоит раньше общего `ValueError`, иначе синтаксическая ошибка выводилась бы как ошибка структуры. `UnicodeDecodeError` тоже подкласс `ValueError` и обрабатывается раньше него.
- **Почему результаты не перезаписываются при ошибке.** `leaders.json` и `selected.json` открываются для записи только после успешного чтения и проверки `todos.json`.
- **Ключи-числа.** Идентификаторы пользователей хранятся и сравниваются как `int`, поэтому `9 < 10` и лидеры сортируются правильно. В строки они превращаются только при выводе (`", ".join(str(user_id) ...)`).
- **Тесты без сети.** `test_analysis.py` импортирует только `analysis.py`, где нет сетевых вызовов. В `fetch_profile.py` и `profile_menu.py` запрос выполняется только в `main()` под `if __name__ == "__main__":`.
