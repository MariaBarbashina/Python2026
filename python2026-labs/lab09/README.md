## Дополнительный модуль: рекурсия

Трассировка `factorial(3)` — фактический вывод `recursion.py`:

```text
вызов factorial(3)
  вызов factorial(2)
    вызов factorial(1)
      вызов factorial(0)
      возврат 1 из factorial(0)
    возврат 1 из factorial(1)
  возврат 2 из factorial(2)
возврат 6 из factorial(3)
```

Вызовы идут с `3`, `2`, `1`, `0`. На `0` срабатывает базовый случай. Затем значения возвращаются в обратном порядке: `1`, `1`, `2`, `6`.

Рекурсивная и итеративная версии сравнены для всех чисел 0–20: результаты совпали, от `0! = 1` до `20! = 2432902008176640000`. Предел глубины рекурсии не менялся.

## Ответы на вопросы защиты

- **Какую ошибку выявляет таблица 2×3.** В квадратной таблице количество строк и столбцов совпадает, поэтому ошибку «перепутаны строки и столбцы» (например, `range(len(matrix))` вместо `range(len(matrix[0]))`) можно не заметить. У таблицы 2×3 длины разные: ошибочный код либо вернёт 2 суммы столбцов вместо 3, либо упадёт с `IndexError`.
- **Почему нельзя повторять одну изменяемую строку.** `[[0] * columns] * rows` создаёт внешний список из `rows` ссылок на один и тот же внутренний список. Изменение `matrix[0][0]` будет видно во всех строках. Поэтому каждая строка создаётся заново в цикле (`for _ in range(rows)`), а в `table.py` для каждой строки создаётся новый список `new_row` / `pattern_row`.
- **Копия внешнего списка и копирование строк.** `matrix.copy()` создаёт новый внешний список, но его элементы — те же объекты-строки, поэтому `copy[0][0] = 9` изменит и исходную матрицу. `[row.copy() for row in matrix]` копирует каждую строку и даёт полностью независимую таблицу чисел. В тестах это проверено: изменение `result[0][0]` не затронуло исходную матрицу.
